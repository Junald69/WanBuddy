# チェックイン画面とメモリ内モック

## 参照した仕様・今回の範囲

起点は main の 55c208b。ユーザー提示の MVP と、既存の Welcome の
「友達限定・手動チェックイン・時間で自動解除・位置情報を使わない」方針を引き継ぐ。
詳細 PRD 自体は main にないため、未統合の `feature/m2-db-rls` の README / 在場 RPC / 施設マスタを
読み取りだけ行い、将来の API と用語・期限・置換条件を合わせた。
参照時点の DB 設計コミットは `aff8cbda3ea55d87fa772a81179aa7d8fd6e4f24`。
**そのブランチをマージしたり、SQL をコピー・実行・適用したりはしていない。**

- https://github.com/Junald69/WanBuddy/blob/aff8cbda3ea55d87fa772a81179aa7d8fd6e4f24/supabase/README.md
- https://github.com/Junald69/WanBuddy/blob/aff8cbda3ea55d87fa772a81179aa7d8fd6e4f24/supabase/migrations/20261028120007_rpc_presence.sql

今回の UI は Debug / Beta の `DEV_LOGIN` 内で動くメモリ内モック。
Supabase への在場 RPC / テーブルアクセス、DB 変更、位置情報取得、バックグラウンド送信は行わない。
通常のログインは既存のまま。ログイン済みなら自分のプロフィールの犬を選択できる。
モック単体の SwiftUI Preview では架空の飼い主と犬を表示でき、認証・DB 不要で画面を確認できる。
架空の友達が実際に在場しているような表示はせず、友達一覧は準備中と表示する。

## 画面

ホームの「今いるよ」「これから行くよ」で保存確認用のシートを開く。
犬 1〜5 頭、予定の場合は到着日時、公開範囲を選び、モック保存する。
ホームでは自分の有効な状態・犬・到着予定・自動解除日時を表示し、確認ダイアログから取り消せる。
予定時刻を過ぎても「今いるよ」への自動昇格はせず、到着時に本人が手動登録する。

モックであること、共有しないこと、再起動で消えることを常時明示する。
公開範囲の選択は記録するだけで、friends を選んでも今回は送信しない。
メモリ内状態はホームの子 View に所有させ、ユーザー ID を View identity に含める。
ログアウトでメイン画面が破棄され、別ユーザーに前ユーザーの状態を持ち越さない。
他タブへの切り替えは同じホーム View の状態を保持する。アプリの再起動・View の再生成では消える。
UserDefaults へ在場履歴や飼い主 ID を追加保存しない。

## 期限・時刻の仕様案（DB 設計の提案値に整合）

| 状態 | 期限 | 受付 |
|---|---|---|
| 今いるよ（now） | 登録から 180 分と、当日の閉園時刻の早い方 | 施設の開園時間内のみ |
| これから行くよ（planned） | 到着予定 + 60 分と、その予定日の閉園時刻の早い方 | 到着予定が開園時間内、現在の -2 分〜+24 時間 |

- 施設はたつみの森ドッグランのモックマスタ。開園 06:00、閉園 21:00、`Asia/Tokyo`。
  06:00 は受付可、21:00 ちょうどは不可。臨時閉園や当日の実際の営業状況は取得しない。
- 予定は登録時刻が閉園中でも、予定日時が翌日の開園時間内なら登録可。
  UI の日時選択は基本的に現在以降。コアの -2 分許容は既存 DB 設計の端末ずれ・入力遅延許容に合わせたもの。
- `expiresAt` ちょうどで失効する。期限の正本は表示上の残り時間ではなく絶対日時。
- `Date` を UTC 相当の絶対時刻として保持し、JSON 化時は ISO 8601 を想定する。
  営業時間と表示は施設タイムゾーンを使う。端末のタイムゾーンで開閉園判定を変えない。
- 読み取り時に `startedAt <= now < expiresAt` を検査し、タイマーや将来の cron が止まっても期限切れを有効扱いしない。
- モックは同時に採取した端末時刻と単調増加の systemUptime の両方で期限を確認する。
  時計が遅く進んでも uptime 上の期限を超えたら解除する。時計の巻き戻し / uptime の逆転は状態を解除する。
  進めた時計で一度失効した状態を、時計を戻して復活させない。
- フォアグラウンドは毎秒、アプリ復帰時と登録・取り消し操作の直前にも更新する。
  OS がアプリを止めている間にタイマーが動く前提にしない。失効通知・バックグラウンドタスクは未実装。
- 実サービスではサーバー発行の時刻・期限を正本にし、クライアントで TTL を決定しない。
  サーバー時刻の同期に失敗した際は古い在場を断定表示しないことを推奨する。

公開の仕様決定前に期限値を変更する場合は、将来の DB 定数とこのポリシーを同時に照合する。
今回は自動延長しない。期限が切れたら利用者の明示操作で再登録する。

## データモデル・状態遷移

`WanBuddyCore/CheckIn` に UIKit / SwiftUI 非依存のモデルとポリシーを配置する。

- CheckInRecord: id / ownerID / facilityID / dogIDs / status / visibility /
  plannedAt / startedAt / expiresAt / endedAt / endedReason
- status は DB の `now` / `planned`、公開範囲は `private` / `friends` に対応。
- endedReason は `manual` / `cancelled` / `expired` / `replaced` / `switched_to_now`。
- dogIDs は飼い主の所有犬からのみ、重複除去後 1〜5 頭。
- 今いるよは全施設で 1 件、予定も全施設で 1 件まで。
  同じ種類の新規登録は前の状態を replaced で終了。
- 今いるよ登録は同じ施設の予定を switched_to_now で終了させる。
  別施設の予定は維持する。予定の登録は既存の今いるよを解除しない。
- 取り消しは now が manual、planned が cancelled。取り消しは冪等。
  既に失効した場合は expired を保持し、未知 / 別セッションの ID は変更しない。
- 不正な新規入力で現在の有効状態を置換しない。
- CheckInSession は所有者単位の値型で、最新 10 件までの遷移をメモリ内に保持する。
  履歴一覧を外部公開する API は提供しない。リセット・View 破棄で消える。

施設 ID は明確に `demo-...` として実際の Supabase UUID と混同しない。
将来は facility code `tatsumi-no-mori-dogrun` からサーバーの UUID を取得して変換する。
モデルの Codable はそのまま SQL 行へ書き込む契約ではない。将来の DTO / RPC アダプターで ID・日時・列名を明示変換する。
友達の在場は ownerID / facilityID / status / plannedAt / expiresAt を基に組み立てられるが、
現在このモデルに友達のプロフィールやメール、犬の個人情報を埋め込まない。

## 公開範囲・安全性

- 今回は **自分のみが既定**。既存 DB 設計の RPC 既定 friends より保守的な UI 初期値とする。
  実接続時は必ず visibility を明示送信し、サーバーの既定に依存しない。
- 公開・全員・地図上での公開は作らない。GPS・自動到着判定・常時追跡は行わない。
- 実接続では accepted の友達のみ、双方どちらかのブロックを最優先で除外。
  private は本人のみ。解除された友達や期限切れはキャッシュにも残さない設計が必要。
- 犬の公開範囲は在場の公開範囲と別途適用する。友達に owner の状態が見えても dogIDs / 犬情報すべてを
  自動開示しない。DB 側の presence_board と犬の可視性を照合するまで友達一覧へ接続しない。
- このモックの所有犬検査や所有者単位セッションは認可の代わりではない。
  Supabase 接続時には auth.uid、RLS / RPC、所有権検査、ブロック、原子的な置換をサーバー側で必須にする。

## 手動確認（macOS 実行は別途承認時のみ）

1. Debug / Beta でログイン・初期プロフィール作成後、ホームに「モックで試用中」が出る。
   UI 単体なら CheckInDemoPanel の Preview の架空データを使う。
2. 今いるよを開き、犬を選択、自分のみのまま保存する。犬・期限・自分の状態が表示される。
3. 犬をすべて外すと保存できない。6時前 / 21時以降の今いるよはエラーになり、既存の状態は置換されない。
4. 予定の画面で日付・到着時刻・公開範囲を選ぶ。24時間超、営業時間外は保存できない。
   閉園中なら翌日6時以降の予定を使う。
5. 取り消しの確認ダイアログで「戻る」なら維持、「取り消す」なら消える。
6. 予定から今いるよを登録し、予定終了と now の表示を確認する。
7. 「モックの有効期限を試す」で時刻を進め、期限切れ・閉園後の表示を確認する。
   **この時計はモック内だけ**で、端末時計・Supabase 時刻は変更しない。予定は到着時刻＋60分まで残る。
8. 実時刻に戻すと時計巻き戻しとして有効状態が解除される。自動復活しない。
9. バックグラウンドから戻った後も期限切れが除外される。ログアウト・別ユーザー・再起動で前の状態が残らない。
10. Release にはモック画面をコンパイルしない。既存の環境分離・Release モック除外チェックを維持する。
